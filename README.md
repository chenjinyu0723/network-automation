# AI Agent 工业交换机自动配置

本项目是本地单用户 Web 应用。它将用户注入的交换机手册转为型号库与命令知识库，支持手绘拓扑、配置规划、逐台审批下发和验证。

## 开发启动

后端：

```powershell
uv sync --extra dev
uv run uvicorn app.main:app --reload --app-dir apps/api
```

前端：

```powershell
pnpm install --frozen-lockfile
pnpm --filter network-automation-web dev
```

生产构建验证：

```powershell
pnpm --filter network-automation-web run build
```

请从工作区根目录执行这些命令。不要使用 `pnpm --dir apps/web install`：在 pnpm 11.9.0 中它会把工作区包当作独立项目安装，并可能错误报出已批准的 `esbuild` 构建脚本被忽略。

默认后端为 `http://127.0.0.1:8000`，前端开发服务器为 `http://127.0.0.1:5173`。

`data/` 是本机运行数据：SQLite 数据库、原始手册、解包内容、导出文件和日志。目录已被 Git 忽略，禁止将真实 API Key、SSH 密码或设备回显提交到仓库。

## 当前实现范围

- 手册导入：CHM（7-Zip 解包）、HTML、文本、PDF；CHM/HTML 解析支持断点恢复的本地 Worker。
- CHM：解析 TOC、命令页、命令格式、视图、参数、约束、示例、型号候选与证据。华为 S 系列导入器识别有限的子系列规则：S17/S57/S67/S77/S127 分别归入 S1700/S5700/S6700/S7700/S12700；实际准入仍要求目标系列已被当前手册覆盖。
- 型号库：系列 / 产品族 / SKU 层级、证据计数、父级与别名人工修正。设备型号按“`canonical_name`/别名精确命中 → 沿 `parent_id` 上溯到系列 → 与当前手册覆盖系列求交”解析；例如 `S5735`、`S5755` 可由已保存的型号树归属 `S5700`。拓扑型号可选，但写前必须识别到一个被手册覆盖的系列。
- 本地混合检索：命令名精确匹配 + SQLite FTS5 + 可选 OpenAI 兼容 Embedding。向量以 SQLite BLOB 保存，CPU 余弦检索融合；Embedding 未配置、不可用或尚未建索引时自动降级到前两者。
- 拓扑：React Flow 基础编辑器；交换机型号来自已发布型号库。
- 规划：LangGraph 状态机按照“输入校验 → 受约束 LLM 意图精炼 → 显式检索节点 → 受证据命令渲染 → 静态校验 → 人工审批”运行；当前阶段 LLM 仅能输出 Pydantic 校验过的 Intent/检索词，不能输出 CLI 或原生 function call，最终命令仍由确定性渲染和安全校验产生。
- LLM 思考策略：设置页提供 `adaptive`（默认）、`always`、`off`。自适应只在需求理解、检索判断、证据审查、命令计划、命令审查和结果诊断等推理型节点开启 `thinking`；静态校验、保护端口检查、Netmiko 执行和 `save` 不调用 LLM。若 OpenAI 兼容端点拒绝 `thinking`/`chat_template_kwargs`，仅自动重试一次关闭 thinking，并在计划审计中记录降级原因。
- 端口：拓扑填写的端口字符串原样进入命令，例如填写 `GE0/0/0` 就下发 `interface GE0/0/0`。仅在端口去重、保护端口和验证回显比较时，将 `GE` 与 `GigabitEthernet` 归为同一接口，避免别名绕过。首期 VLAN Access 插件只把“交换机直连 PC”的端口纳入每台设备的配置范围；上联、云和交换机互联端口不生成命令，并在写入前再次拦截。
- 执行：已审批设备可逐台执行；写入前再次以同一型号树解析器确认现场 `display version` 回显仍归属审批的手册系列，并检查审批 revision、冻结 SSH 地址、保护端口、前序设备和前快照；运行版本记录到审计但不作为门禁。验证失败不执行 `save`，验证通过才自动保存。PC SSH ping 验收为可选项，仅允许 Linux/Windows ping 命令白名单。

## LLM 全链路演进路线

最终目标是“拓扑 + 用户需求 → 每台设备的可审阅命令”。落地采用分阶段策略：

1. 已完成基础：LLM 受限理解需求并补充检索词，混合检索定位手册证据，确定性编译器生成 VLAN Access 命令。
2. 已完成首个 `CommandPlan`：LLM 输出结构化命令 ID、语法变体、参数、拓扑端口引用和证据 ID；确定性编译器将其编译为 VLAN Access CLI。模型不可用时安全回退到原有确定性模板。
3. 已完成独立 LLM 命令审查：它只能批准或拒绝已编译命令，不能改写 CLI 或触发下发；模型不可用时降级。再下一阶段才是最多两轮的受限修复，每次修复增加 approval revision，仍需用户逐台确认。
4. 扩展阶段：把设备身份确认、拓扑语义、检索补查、执行结果解释和错误诊断接入 LangGraph，但写入、保护端口、验证、自动 `save` 始终由确定性节点控制。

命令生成的硬门槛是：每条写命令必须绑定当前手册中的 `command_id`/语法证据；端口必须来自拓扑；型号必须沿型号树归属当前手册覆盖系列；任一门槛失败即阻断，不用模型自由文本猜命令。

真实设备测试仅使用获授权设备及明确的只读命令。不要触碰未授权端口或设备。

## 已导入华为样例与当前门禁

- `S1700, S5700, S6700 V600R025C00 命令参考.chm` 已入库：8,914 页、8,714 条命令、180 个型号候选、0 个失败页。
- 已授权 eNSP 设备只读检测为 `S5700-28C-HI / V200R001C00`。它归属已注入的 S5700 系列，因而可使用该系列的命令证据；运行版本只作审计记录。系统仍不会接触受保护的 `GE0/0/2`。
- 型号树已验证：`S5735 → S5700`、`S5755 → S5700`。解析只接受同品牌目录中的精确型号名或别名；任一父级映射被拒绝、父链成环、或同一型号解析到多个已覆盖系列时，系统会保守阻断。目录尚未收录的华为设备字符串可按有限的 S17/S57/S67/S77/S127 子系列规则兜底，例如 `S5700-28C-HI → S5700`；若所推导系列不在当前手册覆盖集合中，仍阻断，不做模糊 SKU 猜测。
- 真实试验前，仍须从拓扑页明确标记可操作的 `GE0/0/1`，并逐台审批具体命令。
